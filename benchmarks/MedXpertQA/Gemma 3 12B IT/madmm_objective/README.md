# MedXpertQA: MA-RAG-int + MAD-M2 Objective History Masking

English | [中文](README.zh-CN.md)

This directory records the full 490-question module-transfer comparison with
Gemma 3 12B IT. The objective selector from *Multi-Agent Debate with Memory
Masking* is integrated into MA-RAG-int: the host keeps its solver, retrieval,
aggregation and stopping rules, while the transferred module filters the
previous-round answers shown to the next solver round.

Upstream: [MAD-MM](https://github.com/tmlr-group/MAD-MM), commit
`f02069add08280b764d059a2f06ca0043aa093e2`;
[paper](https://arxiv.org/abs/2603.20215).
Dataset identity and source are in [../DATASET.md](../DATASET.md).

## Full-Benchmark Results

| Condition | Correct / 490 | Accuracy | Difference from MA-RAG-int |
| --- | ---: | ---: | ---: |
| MA-RAG-int | 74 / 490 | 15.10% | -- |
| MA-RAG-int + MAD-M2 objective | 78 / 490 | 15.92% | +4; +0.82 percentage points |
| MA-RAG-int + EDR | 93 / 490 | 18.98% | +19; +3.88 percentage points |

The objective masking condition repairs 12 baseline errors and changes 8
previously correct outcomes to incorrect ones. EDR exceeds objective masking
by 15 correct answers, or 3.06 percentage points. The paired comparison has
31 EDR-correct/objective-incorrect questions and 16 questions with the reverse
outcome. All changed outcomes occur on questions where objective masking ran.

Predictions and paired change IDs for all 490 questions are in
[results/final_scores_490.json](results/final_scores_490.json).

## Transferred Mechanism

For each preceding answer, the score is the geometric mean of the
highest-probability token at each generated position:

```text
score_i = exp(mean_t(max_k(log_probability_i,t,k)))
threshold = sorted(scores, descending=True)[number_of_answers // 2]
keep_i = score_i > threshold
```

This follows the upstream implementation, which names this quantity
`perplexity`; the implemented expression is a top-1-probability score, not
standard negative-log-likelihood perplexity. It does not use gold answers.
The strict threshold is not backfilled on ties.

With eight responses, every observed mask retained four preceding answers
and removed four. All eight next-round solvers receive the same retained
history, in the host's original relative display order. This is history
filtering, not EDR's independent/discussion allocation. The current retrieved
evidence is preserved. The query generator still sees all eight preceding
answers, and produces the host's queries without masking. Scores and masks
are recomputed after each new solver round.

The baseline's initial eight answers and its ordered first query/retrieval
material are reused. Masking starts at round 2 for initially non-unanimous
questions; later solver and retrieval stages are generated by this condition.

## Failures and Configuration

There are 486 completed trajectories, three terminal option-parsing failures
(IDs 26, 179 and 429), and one inherited initial-generation failure (ID 438).
All four count as incorrect. Failed-round answers are retained; item 438
references the shared initial failure.

Settings: Gemma 3 12B IT, BF16; eight answers per solver round; solver
temperature 0.7; query temperature 0; maximum eight rounds; maximum 8,192
generated tokens per solver/query call. Retrieval uses MedCorp, BM25 and
MedCPT, up to four queries per stage, 32 recalled documents and two retained
documents per query.

## Public Files and Schema

- `traces/ma_rag_int_plus_madmm_objective_490.jsonl`: one question per line,
  with all eight full generated answers per retained solver stage, decisions,
  technical failures, query strings and document ID/title/score metadata.
- Each subsequent round's `history_mask` records the eight scores, threshold,
  mask, kept/removed indices, visible history order.
  Response indices are zero-based.
- `results/final_scores_490.json`: final predictions, correctness, paired
  repairs/harms and masking counts.
- `results/execution_audit.json`: score and request checks.

Baseline and EDR traces are in the parent `traces/` directory.
Per-round scores determine each history mask.
For documents hit by multiple queries, exported relevance scores use the
first occurrence in query-index order. Parent and comparator exports use
different score-selection orders; shared document text and order are unchanged.
Relevance scores are metadata, not solver input.

## Integration

`src/madmm_objective.py` implements the objective score and strict-middle
selection described above.
`src/madmm_plugin.py` supplies the actual MA-RAG history-masking hook;
`src/run_marag.py --condition madmm_objective` is its runnable entry point.
See [integration commands](../../../../docs/INTEGRATION.md).
The upstream MA-RAG project and retrieval corpus are obtained separately.
A paired run first creates baseline raw receipts with the upstream adapter,
then maps each question to its baseline receipt directory and applies the
selector to each round's retained responses. Use separate output directories,
compatible baseline receipts and the same model settings. Handle terminal
technical failures in the calling runner and retain them in the scoring
population. The experiment's invalid shared initial item was carried forward
as an inherited failure, without regeneration.

The selector is attributed to MAD-MM; the local code is the MA-RAG transfer
adapter. Package licensing and third-party attribution are defined in the
root `LICENSE.md` and `NOTICE.md`.
